# Video Studio Pro

Один маршрутизирующий skill для полного жизненного цикла видео: **получить → понять → найти → изменить → создать → проверить → экспортировать**.

## 1. Сначала определить намерение

Классифицируй запрос в один или несколько режимов:

1. **Analyze** — транскрипт, краткое содержание, главы, темы, факты, OCR, ключевые кадры, метаданные, комментарии, анализ конкретного таймкода.
2. **Search & Knowledge** — пакетная обработка, индексирование, поиск по коллекции видео, заметки или база знаний.
3. **Edit** — нарезка, склейка, удаление тишины, кадрирование, стабилизация, звук, компрессия, изменение скорости, субтитры.
4. **Repurpose** — Shorts/Reels/TikTok, выделение сильных фрагментов, вертикальный формат, заголовки и CTA.
5. **Generate** — text-to-video, image-to-video, avatar/talking head или video-to-video через доступный API.
6. **Render** — детерминированное видео из HTML/CSS/GSAP, React/Remotion или другого программного проекта.

Если запрос смешанный, выполняй режимы в порядке: **Analyze → Plan → Edit/Generate → QA → Deliver**.

## 2. Не выдумывать доступные инструменты

Перед работой проверь, что реально доступно в окружении:

```bash
ffmpeg -version
ffprobe -version
yt-dlp --version
node --version
python --version
```

Дополнительно проверь наличие требуемых CLI, MCP-серверов и переменных окружения. Никогда не утверждай, что видео обработано или отрендерено, пока не получен фактический выходной файл либо проверяемый результат команды.

Если инструмент отсутствует:

- предложи локальный open-source маршрут прежде платного API;
- дай точную команду установки;
- продолжи теми этапами, которые возможны без отсутствующего компонента;
- ясно отметь, что осталось невыполненным.

## 3. Универсальный входной контракт

Прими один из источников:

- локальный видео- или аудиофайл;
- прямая ссылка на медиа;
- YouTube, Vimeo, TikTok, Instagram, X, Loom, Twitch, Facebook и другие URL, поддерживаемые yt-dlp;
- папка или список ссылок для пакетной обработки;
- сценарий, раскадровка, HTML/React-проект или референс для генерации.

Не скачивай закрытый, платный или защищённый контент без разрешения пользователя. Не обходи DRM и контроль доступа.

## 4. Analyze pipeline

### 4.1 Быстрая разведка

Получить технические характеристики:

```bash
ffprobe -v error -show_format -show_streams -of json INPUT
```

Для URL сначала извлечь метаданные без скачивания, если это поддерживается:

```bash
yt-dlp --dump-single-json --skip-download URL
```

### 4.2 Транскрипция

Порядок выбора:

1. готовые субтитры/транскрипт источника;
2. локальная ASR-модель;
3. облачная транскрипция только при наличии ключа и согласия пользователя.

Сохраняй по возможности:

- текст;
- сегменты с `start`, `end`, `speaker`, `text`;
- SRT/VTT;
- язык и уверенность;
- сведения о модели и параметрах.

### 4.3 Визуальное понимание

Извлекай кадры не равномерно по умолчанию, а по сменам сцен:

```bash
ffmpeg -i INPUT -vf "select='gt(scene,0.30)',showinfo" -vsync vfr frames/frame-%05d.jpg
```

Для быстрого движения или точного диапазона используй burst sampling. Для текста на экране применяй OCR только к отобранным кадрам, а не ко всему видео без необходимости.

### 4.4 Анализ момента

Когда пользователь указывает таймкод или вопрос относится к короткому эпизоду:

- отфильтруй транскрипт по диапазону;
- извлеки кадр до, внутри и после события;
- при быстром действии извлеки серию кадров;
- сопоставь речь, визуальные объекты и экранный текст;
- отдели наблюдаемое от предположений.

### 4.5 Выход анализа

По умолчанию возвращай:

- краткое резюме;
- главы с таймкодами;
- ключевые факты и цитаты с таймкодами;
- визуальные наблюдения;
- спорные или неуверенные места;
- рекомендуемые следующие действия.

## 5. Search & Knowledge pipeline

Для нескольких видео создавай нормализованные sidecar-файлы рядом с источником или в каталоге проекта:

```text
video-id/
  metadata.json
  transcript.json
  transcript.srt
  summary.md
  frames/
  index.json
```

Используй стабильный идентификатор источника и хэш входа. Повторный запуск должен возобновлять обработку и не пересчитывать готовые этапы без причины.

Индексируй небольшие смысловые фрагменты с обязательными полями: источник, начало, конец, спикер, текст, визуальные теги и ссылка на кадр. Ответы по коллекции должны содержать происхождение и таймкоды.

## 6. Edit pipeline

### 6.1 Сначала составить edit decision list

Перед необратимыми изменениями создай план:

```json
{
  "source": "input.mp4",
  "target": "short-vertical.mp4",
  "operations": [
    {"type": "trim", "start": 12.4, "end": 47.8},
    {"type": "crop", "aspect": "9:16", "strategy": "face-or-subject-track"},
    {"type": "captions", "style": "high-contrast-safe-area"},
    {"type": "normalize-audio", "target_lufs": -14}
  ]
}
```

### 6.2 Предпочитать FFmpeg для детерминированных операций

Примеры:

```bash
# точная обрезка с перекодированием
ffmpeg -ss START -to END -i INPUT -c:v libx264 -c:a aac OUTPUT

# масштабирование с сохранением пропорций
ffmpeg -i INPUT -vf "scale=1080:-2" -c:v libx264 -c:a copy OUTPUT

# прожиг субтитров
ffmpeg -i INPUT -vf "subtitles=captions.srt" -c:a copy OUTPUT
```

Для сложного монтажа генерируй `filter_complex` или промежуточные файлы, но сохраняй воспроизводимую команду в `render-command.txt`.

### 6.3 Вертикальная адаптация

При 16:9 → 9:16:

- сначала определить главный объект;
- использовать face/subject tracking при наличии;
- не обрезать важный экранный текст;
- держать субтитры в safe area;
- проверять первые, средние и последние кадры каждого фрагмента.

### 6.4 Субтитры

Субтитры должны быть синхронными, читаемыми и разбитыми по смыслу. Не показывай слишком много слов одновременно. Сохраняй редактируемый SRT/VTT отдельно от прожжённой версии.

## 7. Repurpose pipeline

Для поиска клипов оценивай каждый кандидат по:

- самостоятельности смысла;
- сильному началу в первые 1–3 секунды;
- плотности полезной информации;
- эмоциональному или визуальному изменению;
- отсутствию ссылок на потерянный контекст;
- безопасной длине для целевой платформы.

Возвращай таблицу кандидатов с началом, концом, заголовком, причиной выбора и необходимыми правками. Не обещай «вирусность» как гарантированный результат.

## 8. Generate pipeline

Выбирай модель по задаче, а не по известности:

- text-to-video — новый визуальный материал;
- image-to-video — анимация исходного изображения;
- video-to-video — изменение стиля или элементов с сохранением движения;
- avatar/talking head — речь ведущего;
- motion transfer — перенос движения;
- extend/outpaint — продолжение или расширение кадра.

Перед API-вызовом зафиксируй длительность, разрешение, aspect ratio, FPS, референсы, негативные ограничения и бюджет итераций. Не отправляй частные медиа во внешние сервисы без явного согласия.

При региональных ограничениях или недоступности API переключайся на локальный/программный маршрут и сообщай об ограничении.

## 9. Render pipeline

### HTML/GSAP

Используй, когда важны motion graphics, титры, social overlays, waveform, product tour или детерминированная анимация. Сначала построить конечный layout, затем таймлайн. Выполнять lint/inspect до финального render.

### React/Remotion

Используй для компонентного видеопроекта, повторяемых шаблонов, data-driven сцен и сложной логики. Обязательно проверять композиции, длительность, FPS, загрузку ассетов и переполнение текста.

Рендер считается завершённым только после проверки выходного файла через ffprobe.

## 10. QA gate

Перед выдачей результата проверить:

```bash
ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height,r_frame_rate -of json OUTPUT
```

Также проверить:

- файл открывается и длительность ожидаемая;
- звук присутствует и не клипует;
- нет чёрных/замороженных участков;
- субтитры не выходят за safe area;
- синхронизация речи и изображения приемлема;
- разрешение, FPS, кодек и размер соответствуют цели;
- временные файлы не перепутаны с финальным артефактом.

## 11. Формат ответа пользователю

Всегда разделяй:

1. **Что выполнено** — только подтверждённые действия.
2. **Результаты** — файлы, команды, таймкоды или вывод анализа.
3. **Ограничения** — отсутствующие инструменты, качество источника, API/региональные ограничения.
4. **Воспроизводимость** — основные команды и параметры.
5. **Следующий лучший шаг** — максимум один, наиболее полезный.

## 12. Политика надёжности

- Не выдавай догадку за увиденное в кадре.
- Не создавай ложные цитаты или таймкоды.
- Не удаляй оригинал.
- Не перезаписывай входной файл без прямого указания.
- Не раскрывай API-ключи в логах и командах.
- Не объединяй несовместимые инструкции слепым копированием: маршрутизируй по намерению и доступным инструментам.
- Для долгих процессов сохраняй промежуточные результаты и поддерживай повторный запуск.
